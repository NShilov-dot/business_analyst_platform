# Голосовые ходы (Фаза 1): дизайн

Утверждённые решения (2026-08-25): без живых партиалов (это Фаза 1b);
автопрослушка после ответа — по тумблеру «Голосовой режим»; TTS — **Piper**
(MIT, голос `ru_RU-irina-medium`, движок спрятан за роутом — заменим при
желании). Ключевое упрощение скоупа: ассистент ведёт интервью по-русски,
поэтому **синтез нужен только русский** — узбекская речь пользователя уже
покрыта GigaAM на входе.

## 1. Что строим (и что нет)

Цикл «walkie-talkie» в intake-чате:

```
[тумблер «Голосовой режим» ON]
  → слушаем (микрофон + автостоп по тишине ~1.8 с)
  → транскрибация (существующий POST /v1/intake-chat/transcriptions → bap-asr)
  → автоотправка сообщением (существующий sendText)
  → ответ ассистента (существующий send_message, без изменений)
  → озвучка ответа (НОВОЕ: POST /v1/intake-chat/speech → bap-asr /synthesize)
  → снова слушаем  (пока тумблер включён)
```

НЕ входит в Фазу 1: живые партиалы (никакого WebSocket), barge-in
(перебивание голосом — но клик по микрофону во время озвучки глушит её и
начинает слушать), стриминг LLM-ответа, узбекский TTS, изменение
LLM-контракта. Бюджет задержки хода: ~4–8 с (транскрибация 1.5–3 с на тёплом
контейнере + LLM 2–4 с + синтез 0.3–0.8 с) — приемлемо для v1, оптимизации
после партиалов.

## 2. Изменения по слоям

### 2.1 Modal (`services/asr/`) — роут синтеза на том же контейнере

TTS живёт в **том же контейнере bap-asr**, а не отдельным приложением:
Piper — CPU-ONNX, ~50 МБ, а контейнер в голосовом цикле и так тёплый после
транскрибации → синтез без холодного старта. Отдельный CPU-контейнер дал бы
свой cold start в каждом цикле — хуже.

- `modal_app.py`:
  - image: `pip_install(..., "piper-tts")` (тянет onnxruntime CPU).
  - prefetch: скачать голос `ru_RU-irina-medium` (`.onnx` + `.json` c
    HF `rhasspy/piper-voices`) в Volume рядом с весами.
  - `@modal.enter()`: загрузить PiperVoice (мгновенно).
  - Роут `POST /synthesize` — JSON `{"text": "...", "voice": "irina"}` →
    `audio/wav` bytes (22.05 кГц, piper-нативный). Кап на длину текста
    2000 символов (реплики ассистента короче), 422 на пустой текст.
- `config.py`: `PIPER_VOICE = "ru_RU-irina-medium"`, `SYNTH_TEXT_MAX = 2000`.
- Тесты: юнит на кап/пустой текст (без модели), живой смоук в acceptance.

### 2.2 Backend (`modules/ai_structuring`)

- `domain/ports.py`: метод `synthesize(text: str) -> bytes` в
  `TranscriptionPort` (порт уже «голосовой» — переименовывать не надо;
  `_DisabledTranscriber.synthesize` кидает `TranscriptionUnavailableError`).
- `infrastructure/transcription_gateway.py`: `synthesize()` — POST
  `{url}/synthesize`, тот же клиент/таймауты/след за 303; non-200 →
  `TranscriptionUnavailableError`; возвращает bytes.
- `interface/router.py`: `POST /transcriptions/speech`, JSON `{"text": str}`
  (Pydantic, max_length 2000) → `Response(content=..., media_type="audio/wav")`.
  Без SessionDep (по тем же причинам, что transcribe); auth через
  router-level deps; логировать `principal.subject`. Глобальный 1-MiB
  body-лимит НЕ мешает (запрос — маленький JSON; лимит на запрос, не ответ).
- Тесты: гейтвей (MockTransport: happy/non-200/redirect), эндпоинт
  (fake port, 200 + audio/wav; 503 при выключенной фиче; 422 на пустой текст).

### 2.3 Frontend

- `api/intakeChat.ts`: `synthesizeSpeech(text) -> Blob` (fetch с
  credentials, как postForm, но JSON-запрос и blob-ответ).
- **Тумблер «Голосовой режим»** в композере активного чата (иконка
  Volume2/VolumeX): состояние в `useState` + `localStorage` (переживает
  перезагрузку). Включение тумблера = user gesture → здесь же «разблокируем»
  воспроизведение (создаём/резюмим AudioContext) — обход autoplay-политики
  iOS/Safari, где `audio.play()` без жеста запрещён.
- **VAD-автостоп** в `VoiceRecordButton`: у нас уже есть AnalyserNode для
  волноформы — добавляем RMS-детектор тишины: первые ~300 мс калибруют шумовой
  порог, автостоп после 1.8 с тишины, но не раньше 1 с речи; ручной стоп
  остаётся. Активен только в голосовом режиме (обычная запись — как сейчас).
- **State machine** в IntakeChatPage (voice mode ON):
  `listening → transcribing → thinking → speaking → listening`.
  - `speaking`: после ответа `sendText` дёргаем `synthesizeSpeech(reply)`,
    играем через `<audio>`; бабл ответа уже на экране.
  - Прерывания: клик по микрофону в `speaking` → стоп звука → `listening`;
    выключение тумблера в любом состоянии → стоп всего, возврат к ручному
    режиму; Esc = выключить тумблер; finalize/submitted → стоп всего.
  - Ошибка синтеза НЕ ломает ход: тост + текстовый ответ уже виден,
    цикл продолжает слушать (озвучка — best-effort).
  - Автопрослушка НЕ стартует, если вкладка неактивна (`document.hidden`).
- Индикация: пока слушаем — существующая полоса записи; `speaking` — иконка
  динамика на бабле ответа + кнопка «стоп».

## 3. Приватность и безопасность

- Микрофон включается сам ТОЛЬКО при явно включённом тумблере; выключение —
  в один клик/Esc; состояние видно постоянно (полоса записи).
- Синтезируемый текст — реплики ассистента (не ПДн пользователя) — уходит на
  Modal, как и остальной пилотный трафик; новых классов egress нет.
- Rate limit: `/speech` попадает под общий 30 писем/мин; отдельный кап не
  нужен (CPU-синтез копеечный).

## 4. Риски и как их гасим

| Риск | Митигация |
|---|---|
| Piper звучит «синтетически» | Послушать 10 доменных фраз до мержа (acceptance-шаг); замена движка = только `services/asr` + prefetch, порт/роут/фронт не трогаются |
| VAD в шумном опенспейсе стопается рано/поздно | Порог калибруется от шумового пола; константы в одном месте компонента; ручной стоп всегда доступен |
| iOS/Safari autoplay | Разблокировка аудио на клике по тумблеру (см. 2.3) |
| Цикл «зациклился» (VAD ловит звук колонок) | Автопрослушка стартует только ПОСЛЕ конца воспроизведения; наушники — рекомендация в подсказке тумблера; barge-in по звуку не делаем |
| Долгий ход (4–8 с) раздражает | Уже есть баблы «Расшифровка…»/«печатает»; добавить звуковой сигнал начала прослушки (короткий бип из WebAudio, без ассетов) |

## 5. Порядок реализации

1. `services/asr`: piper в image + prefetch голоса + `/synthesize` + смоук
   curl-ом (деплой, послушать wav).
2. Backend: порт/гейтвей/роут + тесты (`make check`).
3. Frontend: `synthesizeSpeech` + тумблер + VAD-автостоп + state machine
   (`make fe-build`).
4. E2E чек-лист: полный цикл ru; полный цикл uz (голос uz → текст uz →
   ответ ru озвучен); выключение тумблера в каждом состоянии; iOS Safari;
   ошибка синтеза (погасить Modal) → цикл живёт без звука.

## 6. Явно отложено

Фаза 1b: живые партиалы (WebSocket бэк + WS-прокси до Modal + стриминг-режим
GigaAM чанками; Modal WS подтверждён: RFC 6455, кадр ≤ 2 МиБ). Фаза 2: полный
дуплекс с barge-in (Pipecat/LiveKit). Узбекский TTS — только если появится
требование озвучивать ответы на uz (спайк: MMS-TTS vs mohir.ai).
